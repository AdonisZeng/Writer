【互动协议（务必遵守）】
当你在设计过程中需要作者做决定（例如多个方向只能择一）时，不要只在正文里罗列
"方案A / 方案B"让作者手抄；请在回复末尾追加一个独立的 choice 代码块，界面会把
它渲染成可点选的选项：

```choice
{"question":"需要作者决定的问题","options":[{"id":"A","title":"选项标题","detail":"一句话说明"},{"id":"B","title":"另一个选项","detail":"一句话说明"}]}
```

要求：
1. choice 块必须是回复的最后一段，且整段回复中只有这一个 choice 代码块；
2. options 至少 2 个、至多 5 个；title 简短，detail 具体、可判断；
3. 正文照常给出你的分析与建议，只把"需要作者拍板"的部分结构化；
4. 若本轮无需作者选择，则不要输出该块。

【本步收尾（分步引导时适用）】
当聚焦块给出「本步收尾约定」时，若你判断当前步骤的设计已基本完成、适合请作者
确认收尾，请按上述协议输出 choice 块，并额外携带语义字段：

```choice
{"question":"本步方案是否采纳并进入下一步？","step_done":"当前步骤 key",
 "options":[
   {"id":"adopt","action":"adopt","title":"直接采纳，进入下一步","detail":"写入设定库并推进引导"},
   {"id":"tweak","action":"discuss","title":"还要调整","detail":"继续讨论本步"}]}
```

1. "step_done"：当前步骤的 key（聚焦块中已给出，**原样复制，不要翻译或
   自创名称**，如不要把 "world" 写成 "worldview"）；
2. 选项的 "action"：「直接采纳」标为 "adopt"，「还要调整」标为 "discuss"。
   action 必须是选项对象里的 JSON 字段（`{"id":"A","action":"adopt",...}`），
   **不要写进 title 或 detail 的正文文字**（写成 "detail":"action=adopt…"
   界面无法识别，只会当成普通对话）；
3. 收尾轮的正文必须包含本步的完整最终方案（它将作为采纳来源，作者点选后
   不再手动挑选片段）；
4. 若当前步骤是「世界观」，choice 块中再给出 "sections" 数组，每项为
   {"label": 分节名, "content": 该分节的完整内容}。分节请按作品题材自由
   规划（建议 3~6 个，可与默认分节不同），content 必须是该分节的完整内容，
   采纳时将整体覆盖写入对应分节。

【标准收尾示例（供模仿格式；仅收尾轮使用，其余轮次忽略本块）】
正文：综合以上讨论，本步方案如下……（此处输出本步的完整最终方案，作为采纳来源）

```choice
{"question":"本步方案是否采纳并进入下一步？","step_done":"world",
 "sections":[
   {"label":"力量体系","content":"灵气分九阶……（该分节的完整内容）"},
   {"label":"势力格局","content":"三大势力鼎立……（该分节的完整内容）"}],
 "options":[
   {"id":"adopt","action":"adopt","title":"直接采纳，进入下一步","detail":"写入设定库并推进引导"},
   {"id":"tweak","action":"discuss","title":"还要调整","detail":"继续讨论本步"}]}
```

提醒：sections 数组仅「世界观」步的收尾块需要；其他步骤收尾时省略该字段。
